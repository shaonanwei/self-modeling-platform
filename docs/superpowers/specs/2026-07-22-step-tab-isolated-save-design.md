# 编辑步骤 Tab 隔离保存设计

## 背景

编辑已有步骤时，基本信息页的“保存&关闭”会构造一个空的 SQL 配置，并通过步骤更新接口覆盖 `step_config` 和 `sql_statement`。因此，仅修改步骤名称或描述也会清空此前保存的 SQL。

## 目标

- 基本信息 Tab 只修改步骤名称和步骤描述。
- SQL 配置 Tab 只修改 SQL 语句和查询配置。
- 保存任一 Tab 时，另一个 Tab 已保存的数据保持不变。
- 新增和插入步骤继续使用现有创建流程。
- SQL 更新继续执行现有单条只读 `SELECT` 校验。

## 非目标

- 不调整编辑步骤界面布局和按钮文案。
- 不新增 SQL 草稿、自动保存或并发编辑提示。
- 不新增后端 API 路径。

## 方案

继续使用现有步骤更新接口，但将其定义为字段级合并更新：前端只发送当前 Tab 的字段，后端读取数据库中的现有步骤，用原值补齐请求中未提供的字段，再执行更新。

### 基本信息 Tab

编辑已有步骤时，“保存&关闭”只发送：

- `stepName`
- `stepDesc`

请求不携带 `stepConfig` 和 `sqlStatement`。后端保留原步骤的 SQL 配置和 SQL 语句，也不因基本信息变化而重新校验或清空 SQL。

### SQL 配置 Tab

编辑已有步骤时，“保存”只发送 `stepConfig`。现有配置解析逻辑从中提取、校验并保存：

- `sqlStatement`
- `queryConfig`

请求不携带步骤名称和描述。后端保留原步骤的基本信息。

### 新增和插入步骤

新增或插入时数据库中没有可合并的旧记录，因此保持现有行为：

- 在基本信息页保存时创建一个尚未配置 SQL 的步骤。
- 在 SQL 配置页保存时创建包含基本信息和 SQL 配置的步骤。

## 后端合并规则

步骤更新服务先读取并校验目标步骤属于当前模型，然后按以下规则合并：

- 请求字段为 `null`：保留数据库原值。
- 请求字段为非 `null`：使用请求值。
- 空字符串是明确值，不等同于未提供，因此允许清空步骤描述。
- 仅当请求携带 `stepConfig` 时才解析和校验 SQL。

合并完成后继续调用现有 Mapper 更新方法，以保持 API 路径和数据库写入流程兼容。

## 错误处理

- 步骤不存在或不属于当前模型时，保持现有错误行为。
- SQL 配置不合法时拒绝整个 SQL Tab 更新，基本信息保持不变。
- 基本信息校验失败时不发送更新请求。

## 测试

- 后端回归测试：只更新基本信息时，Mapper 收到原有 `stepConfig` 和 `sqlStatement`。
- 后端回归测试：只更新 SQL 配置时，Mapper 收到原有步骤名称和描述。
- 保留并运行现有 SQL 安全测试，确认只读 SQL 校验没有被绕过。
- 前端回归测试：基本信息编辑分支不提交 `stepConfig`，SQL 编辑分支不提交基本信息字段。
- 运行前端构建，并在浏览器中执行实际编辑步骤冒烟验证。

## 兼容性

- API 路径不变。
- 新增、插入和完整步骤更新流程保持可用。
- 对仍发送完整对象的旧调用方，后端继续使用其显式提供的字段。
